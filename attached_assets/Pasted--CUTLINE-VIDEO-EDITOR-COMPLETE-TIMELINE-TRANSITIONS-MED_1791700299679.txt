# 1. MEDIA SECTION — FOLDER-BASED PROJECT LIBRARY

Redesign the Media section to organize saved editable projects into user-created folders.

### Initial empty state

- On first launch, when there are no saved projects, display **“Drop your first project”**.
- Provide an obvious way to import a video and start editing.
- Once media is imported, open a usable editing session.
- Do not create a project folder automatically just because the user imported a video.

### Folder and export workflow

When the user exports a project:

1. Allow the user to select an existing project folder or create a new folder.
2. If creating a folder, ask for its name.
3. Save the editable project inside the selected folder's project library.
4. Save the exported video in the appropriate folder or associated export location.
5. After a successful save/export, update the Media section automatically.
6. Prevent duplicate folder creation when exporting an existing project again.
7. If the user is editing a saved project, default to its current folder while allowing another destination to be selected.
8. If the user is editing a newly imported clip, do not silently assign it to an unrelated folder.
9. Keep the project's identity stable when the user saves or exports it repeatedly.

### Folder limit

- Allow a maximum of **10 folders**.
- When the limit is reached, disable new-folder creation and explain that the user must select an existing folder or remove one first.
- Each folder may contain any number of projects, subject to available storage.
- Enforce the limit in the actual folder-creation logic, not only in the UI.

### Expandable folders

- Display each folder as a clear, expandable or collapsible row/card.
- Clicking a folder expands it downward to reveal all saved projects inside.
- Clicking again collapses it.
- Display the folder name and project count.
- Each project entry should show a thumbnail, project name, duration, and last-modified date when available.
- Selecting a project must reopen its complete editable timeline, not merely play the exported MP4.
- Add appropriate rename and delete actions.
- Require confirmation before destructive operations.
- Before deleting a folder, clearly explain what happens to its projects and exported files.
- Preserve folder/project relationships after restarting the application.

### Find Media search and plus button

The Media section must include a working **Find Media** search bar and a **plus (+)** button.

**Search:**

- Search folders and saved projects by name.
- Filter results as the user types.
- Keep matching projects visible inside their parent folders.
- Provide a clear-search control and a useful empty-results message.
- Searching must not change or delete project data.

**Plus button:**

- Open the native file picker to import a separate media clip.
- Start a separate editing session if no saved project is selected.
- Do not overwrite or replace an existing saved project.
- Do not immediately create a project folder after import.
- Let the user edit the clip and choose a folder during saving/export.
- After a successful export, save the project in the selected folder and show it in the Media section.

# 3. RESTORE AND SEPARATE TIMELINE TRACKS

Maintain separate, persistent tracks with clear labels:

1. **Video Track:** Main/base video.
2. **Clip Track:** Additional video clips that overlay the base video.
3. **Audio Track:** Audio clips, where supported.
4. **Text/Title Track:** Text and title overlays.
5. **Transition Track:** Visible transition regions linked to clips or supported boundaries.

The Video Track and Clip Track are different tracks with different purposes.

- Adding or modifying the Clip Track must never remove, replace, or disable the original Video Track.
- Inspect the existing implementation to determine why the Video Track was removed or replaced, then fix the underlying cause.
- Preserve the existing timeline controls and project compatibility wherever possible.
- Ensure track assignments are stored persistently and restored when reopening projects.
- Keep selection, dragging, trimming, splitting, and deletion behavior consistent with the existing timeline architecture.

# 4. CLIP TRACK OVERLAY BEHAVIOR

Implement correct timeline-based layering and playback.

- The base video plays normally wherever no overlay clip covers the current timeline position.
- An overlay clip on the Clip Track temporarily covers the base video for the overlay's exact timeline duration.
- When the overlay ends, the base video resumes at its corresponding timeline position.
- Multiple overlay clips must work without shifting or deleting the base video.
- Define predictable overlap behavior. A higher video layer may take visual priority when overlay clips overlap.
- Keep clip position, duration, track assignment, and playback time accurate.

**Example:** If the base video runs from 0–60 seconds and an overlay clip is placed at 10–15 seconds:

- 0–10 seconds: base video.
- 10–15 seconds: overlay clip.
- 15–60 seconds: base video resumes at its corresponding timeline position.

Support independent:

- Dragging and moving.
- Trimming and resizing.
- Splitting.
- Selecting.
- Deleting.
- Adjusting supported overlay/compositing settings.

Maintain audio synchronization and ensure the preview and final exported video use the same layering rules.

Do not implement overlay behavior only as a visual timeline decoration. It must affect actual playback and exported output.
